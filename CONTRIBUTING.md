# Участие в разработке

Приложение поставляется пользователям одним файлом `tinvest_analytics.py`. Ядро — только стандартная библиотека Python 3.8+; отдельные функции могут подгружать чистые Python-пакеты по требованию (см. «Дополнительные библиотеки» ниже). Для удобства разработки исходники разбиты на части в `src/`, а итоговый файл собирается скриптом.

## Структура

```
src/py/NN_<имя>.py        фрагменты Python, склеиваются по порядку имён (не пакет, без импортов между ними;
                          поздние фрагменты используют глобальные имена ранних)
src/web/shell.html        каркас страницы с маркерами {{CSS}} и {{JS}}
src/web/css/NN_<имя>.css  стили по порядку имён
src/web/js/NN_<имя>.js    фрагменты JS по порядку имён (по одному на раздел/страницу)
build.py                  сборка -> tinvest_analytics.py
tinvest.py                лаунчер с автообновлением (скачивает релизный файл tinvest_analytics.py)
```

Страница (`PAGE`) собирается из `src/web/` и подставляется вместо маркера `{{PAGE}}` в `src/py/15_page.py`.

## Как вносить изменения

1. Правьте файлы в `src/`. **Никогда не правьте `tinvest_analytics.py` вручную**: он генерируется.
2. Выполните `python3 build.py` и закоммитьте и `src/`, и обновлённый `tinvest_analytics.py`.
3. `python3 build.py --check` завершается с ошибкой, если закоммиченный файл не совпадает со свежей сборкой (для CI и ревью).

Фрагменты склеиваются побайтово, без добавления символов, поэтому новый фрагмент нужно начинать и заканчивать с учётом переводов строк. Чтобы добавить фрагмент, создайте файл с нужным числовым префиксом.

## Локальный запуск

```
python3 tinvest_analytics.py --no-window --port 8799
```

Порт можно задать и переменной окружения `TINVEST_PORT`. Данные хранятся в `~/.tinvest_analytics` (можно переопределить через `TINVEST_HOME`); для отладки удобно указать отдельный каталог.

## Тесты

Только стандартная библиотека; тесты импортируют собранный `tinvest_analytics.py` (после правок в `src/` сначала `python3 build.py`), данные пишутся во временную папку, сети нет.

```
python3 -m unittest discover -s tests -v
```

- `tests/test_calc.py` — расчёты на известных ответах (доходность, дюрация, стресс, потоки с офертой и амортизацией, прогноз флоатеров, IRR портфеля, НКД, разбор рейтингов, календарь выплат) и совместимость синтаксиса с Python 3.8.
- `tests/test_tbank_import.py` — импорт отчёта брокера Т-Инвестиций на синтетических таблицах (РЕПО, раздел 2, входящие остатки, слияние файлов, откат на общий импортёр).
- `tests/test_vtb_import.py` — импорт отчёта брокера ВТБ на синтетических таблицах («@xl»-ячейки, заключённые/завершённые сделки, сверка с остатками, слияние периодов).
- `tests/test_live_moex.py` — живая сверка нашей доходности с полем YIELD Мосбиржи по ~30 ликвидным облигациям; по умолчанию пропускается. Включить: `TINVEST_LIVE=1 python3 -m unittest tests.test_live_moex -v` (нужен доступ к iss.moex.com; печатает таблицу расхождений).
- CI (`.github/workflows/tests.yml`) на Python 3.10 и 3.12 (совместимость синтаксиса с 3.8 проверяет тест) запускает `python build.py --check` и обычные тесты; живые там пропускаются.

## Релизы

В релиз кладётся собранный одиночный файл `tinvest_analytics.py` и файл контрольных сумм `SHA256SUMS`. Имя ассета должно оставаться ровно `tinvest_analytics.py`: именно его скачивает лаунчер.

## Дополнительные библиотеки

Ядро (портфель, импорт, налоги, экраны) не зависит ни от одного пакета. Функции, которым нужна библиотека, вызывают
`vendor_import("имя")` (`src/py/02b_vendor.py`): колесо скачивается при первом обращении в `~/.tinvest_analytics/lib`,
проверяется по SHA256 из замка `src/py/02a_vendor_lock.py` и импортируется прямо из `.whl`. Если библиотека недоступна
(нет сети, старый Python), функция получает `ApiError` с понятным текстом — остальное работает.

* Добавить библиотеку: строка в `packaging/vendor.txt` (только колёса `py3-none-any`, точная версия и SHA256 с PyPI),
  затем `python3 packaging/vendor_lock.py` и `python3 build.py`. Проверка без сети: `python3 packaging/vendor_lock.py --check`.
* Тяжёлое (numpy, pandas, разбор больших PDF) — на сервере: `server/requirements.txt`, воркер считает, программа получает JSON.
* При релизе CI сам скачивает колёса (по хэшам из замка), кладёт их в релиз как запасной источник и добавляет их
  стандартные модули в сборку приложения.
